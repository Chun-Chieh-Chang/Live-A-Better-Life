安裝與操作手冊

雙擊啟動檔，自動準備環境、啟動服務並登入前端。手冊同時保留備份、資料復原與進階維護說明。

修訂日期：2026-11-01（台北）適用：Node 24 / Bun 1.4.4狀態：Windows 實機待驗收
AUTO

一鍵啟用：不用人工貼指令

將程式解壓並同步到專案後，直接雙擊根目錄的 Start-LifeOS.cmd。正常流程不需要開 PowerShell、不需要逐段執行指令，也不需要輸入登入密碼。

雙擊啟動→自動準備工具／建置→登記排程／啟動→驗證／備份／自動開頁
  • 自動重用 Node 24 與 Bun 1.4.4；缺少時安裝在目前使用者的 LOCALAPPDATA。Node 下載核對官方 SHA-256，Bun 使用 npm 正常完整性驗證，不停用 TLS。
  • 自動初始化本機帳號，新帳號使用高強度隨機憑證；既有帳號與日誌不重設。登入信任目前 Windows 使用者對私有資料夾的存取權。
  • 瀏覽器使用 60 秒、單次有效的登入連結，兌換後立即從網址移除。只在 127.0.0.1 運行，不是公開免密碼登入。
  • 來源沒有變動時跳過重複建置；登入 Windows 後由排程自動啟動並開頁。關機、休眠或未登入時不保證服務持續運行。
  • 系統政策、排程權限或網路受阻時會停止並顯示原因；不會自動降級保護。真正的 Gemini 金鑰仍需安全配置，不會自動捏造。
下方手動安裝與維護指令保留供診斷參考。一般使用只需雙擊 Start-LifeOS.cmd，不用按章節逐項操作。
01

先了解這個版本

本手冊適用於在你的 Windows 電腦上運行「把日子過好」，先供自己使用。採用單一擁有者帳號與 SQLite 資料庫，服務只監聽本機 127.0.0.1，不會自動開啟防火牆、區網或網際網路存取。

程式位置D:\Self-developed_Apps\G3\Live-A-Better-Life
私有資料位置D:\Self-developed_Apps\G3\Live-A-Better-Life-Data
瀏覽器輸入位址http://127.0.0.1:3000
每日備份目標時間03:15（台北時間 UTC+08:00）
保存有兩步：先「儲存今日日誌」，再「上傳已歸檔資料」。只有上傳成功，才代表已寫入這台電腦的 SQLite 資料庫；草稿不會自動上傳。
填寫／草稿→儲存日誌→上傳至本機服務→SQLite＋備份

個人模式的瀏覽器暫存使用 sessionStorage。登出或關閉分頁前，請先上傳或匯出未保存內容。程式升級時保留獨立資料目錄。

驗證範圍：雲端已通過 23 項資料／服務測試、11 項既有瀏覽器流程及個人模式端到端流程。PowerShell 語法與共用流程在 PowerShell 7.5.4／Linux 上通過；Windows PowerShell 5.1、工作排程器、ACL、DPAPI 與你的 D: 磁碟，仍須依本手冊在實機驗收。

03

手動安裝與密碼設定（進階）

一鍵啟用使用無人值守模式，不會要求以下密碼輸入；本節僅供手動維護。

使用一般使用者 PowerShell，進入專案根目錄並執行：

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
.\deploy\windows\Setup.ps1

Setup 會依序做什麼

  1. 檢查 Node 24、Bun 1.4.4 與專案檔案。
  2. 建立專案外的私有資料夾，設定目前使用者、SYSTEM 與管理員的存取權限。
  3. 以鎖定檔安裝依賴，執行 TypeScript 檢查及正式建置。
  4. 若尚無帳號，隱藏輸入提示會要求設定並確認 14–256 字元的擁有者密碼。

密碼透過子程序 stdin 傳入，資料庫只保存雜湊，不寫入命令列或 config.json。重跑 Setup 不會自動重設既有密碼，也不會自動登記排程。

成功訊息：顯示 Prepared. Configuration: 與設定檔位置。若任何安裝、型別檢查或建置失敗，先處理錯誤，再重跑。

自訂資料目錄或連接埠（選用）

PowerShell
.\deploy\windows\Setup.ps1 -DataRoot 'E:\LifeOS-Private' -Port 3001
使用自訂值時，下文所有 ConfigPath 與瀏覽器位址都要改成實際設定。資料目錄必須在專案外，不用網路磁碟；Setup 會拒絕採用沒有既有設定的非空資料夾。

config.json 指向你的 Node 執行檔與程式目錄。換 Node 安裝位置或搬動程式時，先停止服務，再確認設定；不要直接搬移或覆寫資料庫。

執行中的 SQLite 可能同時使用 .sqlite、-wal 與 -shm。不要只複製主檔、刪除 WAL，或將執行中的原始檔當成完整備份；請使用備份指令匯出一致的 JSON。
05

啟動與第一輪驗證

方式一：啟動後自動開啟瀏覽器（建議）

完成 Setup 後，使用以下指令。服務若尚未啟動會另開 PowerShell 視窗，確認就緒後才開啟預設瀏覽器；不會自動建立密碼。此操作需在你的 Windows 電腦執行。

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
.\deploy\windows\Open-LifeOS.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json'

方式二：手動啟動與驗證

視窗 A：啟動服務

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
.\deploy\windows\Start-LifeOS.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json'

此視窗會持續執行，不會立刻回到提示字元；日誌寫入私有資料夾的 Logs。需要手動停止時按 Ctrl＋C，並確認連接埠已釋放。

視窗 B：執行驗證

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
.\deploy\windows\Verify.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json'

預期：顯示 PASS: personal service is ready and bound to loopback。此腳本實際檢查：

  • /healthz：程序能回應。
  • /readyz：資料庫及擁有者帳號已就緒。
  • /api/auth/session：是 personal 模式且帳號已設定。
  • 匿名存取私密資料端點回 401，監聽位址只有 127.0.0.1。

在同一台電腦的瀏覽器網址列輸入 http://127.0.0.1:3000，一鍵啟用會自動登入；只有手動設定密碼的使用者才需要輸入密碼。維持使用此位址，不要與 localhost 交替。

這一階段僅供這台電腦使用；其他電腦或手機無法用此位址連入。若要開放其他裝置，需另做 HTTPS 與網路驗收，不要自行把監聽位址改成所有介面。
06

日常記錄與資料同步

  1. 第一次使用新分頁，按「下載伺服器資料」取回已保存日誌與手冊。新資料庫尚無日誌時，可「匯入原本機工作區」或使用 JSON 備份匯入。
  2. 填寫日誌、選擇狀態，按「儲存今日日誌」。確認沒有儲存失敗訊息。
  3. 按「上傳已歸檔資料」，確認「已上傳至伺服器」。這裡的「伺服器」是你本機的 Node 程序。
  4. 關閉分頁後重新登入、下載，確認內容與日期一致。

遇到版本衝突怎麼辦

兩個分頁若讀取同一版本，其中一個已上傳更新，另一個直接上傳會回 409 並拒絕覆蓋。先把目前分頁資料匯出 JSON，再下載最新伺服器版本比較。系統沒有自動合併；重新整理版本後再上傳，代表你明確選擇取代伺服器內容。

登出與草稿

登出會撤銷該次登入並清除目前分頁的個人模式暫存。未歸檔草稿不會同步；關閉分頁、登出或清除瀏覽器資料前，先完成儲存／上傳，或下載備份。

Obsidian 功能是手動 Markdown 匯出，沒有雙向同步。既有舊版可能混入的示範日誌不會被自動刪除；先備份，再人工整理。

設定登入啟動與每日備份

先確認手動啟動與 Verify 都成功。按 Ctrl+C 停止手動服務後，再執行以下指令，避免兩個程序搶同一連接埠。

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
.\deploy\windows\Install-Tasks.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json'
Start-ScheduledTask -TaskName 'LifeOS-Server'
.\deploy\windows\Verify.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json'
Get-ScheduledTask -TaskName 'LifeOS-Server','LifeOS-Backup' | Get-ScheduledTaskInfo
任務執行方式完成判斷
LifeOS-Server目前使用者登入後啟動；有限次失敗重啟，不重複啟動。Verify 通過，瀏覽器可以登入；不能只看任務存在。
LifeOS-Backup每天 03:15 UTC+08:00；錯過時在條件恢復後執行。確認執行結果及 Backups 中的新檔案。

任務以目前使用者的互動登入運行，不保存 Windows 登入密碼。登出、關機或休眠時，不保證服務與備份持續運行。電腦回到可用且已登入狀態後，確認任務執行結果。若任務登記被拒絕，依主機政策處理，不要直接改成管理員或放寬執行政策。

停止與重新啟動

PowerShell
Stop-ScheduledTask -TaskName 'LifeOS-Server'
Start-ScheduledTask -TaskName 'LifeOS-Server'

先確認舊程序已停止才重新啟動；如果仍有埠占用，先查明程序，不要直接終止所有 Node 程序。

08

立即備份與保留策略

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
.\deploy\windows\Backup.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json'
Get-ChildItem 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\Backups' | Sort-Object LastWriteTime -Descending | Select-Object -First 5

成功條件：命令顯示 Scheduled backup completed.，且能看到新的 life-os-日期-識別碼.json。備份包含日誌與手冊，不包含密碼雜湊或登入 session。

  • 每日 JSON：成功匯出後才清理超過 30 天的本工具備份檔；不刪其他檔案與符號連結。
  • 資料庫內歷史版本：另保存最近 30 次寫入前版本，可在同步區還原；這與每日 JSON 不同。
  • 瀏覽器「匯出備份」：匯出的是該分頁當下已保存資料，未必等於服務端最新版本；「下載伺服器備份」才讀取服務端。
資料庫和預設 Backups 都在同一個 D: 磁碟，不能抵抗磁碟故障。請另外將完成的 JSON 複製到受保護的外接磁碟或備份服務。檔案含私密日誌，不要公開分享。
09

備份還原與密碼管理

A. 只想找回先前日誌

在同步區展開「伺服器歷史備份」，選定版本並確認還原。還原會建立新版本並保留還原前內容；完成後按「下載伺服器資料」更新目前分頁。JSON 檔也可經匯出頁的「匯入備份」載入，確認後再上傳。

B. 離線演練：還原到新的資料庫

先從 Backups 選一份實際存在的 JSON，替換下方第一行。restored.sqlite 必須尚不存在；此操作不會自動切換正在使用的資料庫。

PowerShell
Set-Location 'D:\Self-developed_Apps\G3\Live-A-Better-Life'
$backup = 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\Backups\請替換為實際備份檔名.json'
$restorePath = 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\restored.sqlite'
$previousDb = [Environment]::GetEnvironmentVariable('LIFE_OS_DB_PATH', 'Process')
try {
    $env:LIFE_OS_DB_PATH = $restorePath
    npm run backup -- restore $backup
    if ($LASTEXITCODE -ne 0) { throw 'Restore failed' }
} finally {
    if ($null -eq $previousDb) { Remove-Item Env:LIFE_OS_DB_PATH -ErrorAction SilentlyContinue }
    else { $env:LIFE_OS_DB_PATH = $previousDb }
}

工具先驗證 JSON，再寫入新 DB，拒絕覆蓋既有檔案。新庫不含舊密碼與 session，需要重新設定擁有者密碼。若要正式切換到還原資料，先停止服務、保留原始資料目錄，再依專案設定處理切換並重新驗收；不要把演練檔直接覆蓋 owner.sqlite。

C. 設定中斷或忘記密碼

尚未完成首次密碼設定時，省略 -Reset；要重設既有密碼時才加上此旗標：

PowerShell
.\deploy\windows\Set-OwnerPassword.ps1 -ConfigPath 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\config.json' -Reset

重設會保留日誌，但撤銷全部登入。不要把登入密碼、金鑰或資料庫檔貼到聊天。

10

啟用 Gemini（選用）

未設定金鑰時，日誌仍可保存並使用明確標示的規則備援。需要真實 Gemini 時，以啟動任務的同一 Windows 使用者執行：

PowerShell
Read-Host 'Gemini API key' -AsSecureString | ConvertFrom-SecureString | Set-Content -Encoding ASCII 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\gemini.dpapi'

隱藏輸入金鑰後，停止並重新啟動服務。DPAPI 加密檔綁定 Windows 使用者／電腦；不能當成明文金鑰搬到另一台電腦，也不要使用雲端代理的憑證占位符。

在系統檢查畫面發送測試握手，只有顯示 gemini-api 且教練卡片標示 Gemini 生成，才代表遠端鏈路已驗證。預設 gemini-3.8-flash 尚未經真實金鑰驗證；若帳號不支援，須在實際啟動程序的服務環境設定 GEMINI_MODEL，並重新測試。

限制目前設定
同時模型請求1 個
請求配額每小時 20 次、每 24 小時 100 次；自檢與失敗嘗試也計入
單次大小輸入 32 KiB，輸出最多 2000 tokens
超限 / 失敗429 表示配額或並行限制；503 自檢表示遠端未就緒；卡片會區分 Gemini 與備援

請求數限制不等於帳單金額保證。此手冊交付時，真實 Gemini 呼叫仍未驗證。

11

更新程式與故障排除

安全更新順序

  1. 先把分頁中的日誌儲存並上傳，再立即執行一次備份。
  2. 若用排程啟動，停止 LifeOS-Server；若是手動視窗，按 Ctrl+C 並確認舊程序已結束。
  3. 保留本機程式修改與 .env，同步程式檔；不搬動私有資料目錄。
  4. 重跑 Setup 重新安裝／建置，再啟動、Verify、登入下載並核對資料。

先取得診斷資訊

PowerShell
Get-Content 'D:\Self-developed_Apps\G3\Live-A-Better-Life-Data\Logs\server.stderr.log' -Tail 60
Get-ScheduledTask -TaskName 'LifeOS-Server','LifeOS-Backup' | Get-ScheduledTaskInfo
Get-NetTCPConnection -State Listen -LocalPort 3000
現象處理方式
找不到 node / bun確認工具版本、重開 PowerShell，再執行 Setup。Node 安裝路徑變更後重新產生 config。
腳本被執行政策擋下依組織政策核准或簽署腳本；不要直接設定 Bypass 或停用驗證。
Refusing to adopt a nonempty directory該資料夾未被辨識為本工作區；保留檔案，改選新的專用目錄，不要刪檔強行繼續。
Port / EADDRINUSE可能手動程序與排程同時運行，或另一個程式占用。查明擁有程序後再停止；不要批次終止所有 Node。
Verify 顯示未就緒 / 503查看 stderr 日誌、確認密碼設定完成、DB 路徑及存取權限。不要把「程序存在」當成就緒。
登入失敗 / 429確認使用 127.0.0.1、密碼及 Cookie；登入 15 分鐘最多 5 次嘗試，超限先等待，必要時依密碼重設流程處理。
看不到舊日誌先確認是否已下載伺服器資料、以前是否使用不同瀏覽器來源。從舊版 JSON 匯入，先備份再操作。
